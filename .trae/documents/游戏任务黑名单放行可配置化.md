# 游戏任务黑名单放行可配置化

## Context（为什么改）

今天新增的游戏任务备用完成通道已落地：`TaskAlternative`（400000040 时换 `com.alipay.antfarm.doFarmTask` 伪申报）+ `MiniGameTaskListMap`（自动收集「任务名 → 出现过的任务列表 listTitle 集合」，存 `MiniGameTask.json`）+ 10 处黑名单跳过点的自动放行判据 `!MiniGameTaskListMap.containsScene(title, list)`。

问题：只要任务被收集进表，黑名单就**永远自动放行**，用户无法选择「哪些黑名单游戏任务才走备用完成通道」。

目标（用户原话梳理）：
1. 黑名单机制不变（任务仍在黑名单里，不勾选的照常跳过）；
2. 黑名单里的游戏任务是否尝试完成 → 用户可配置；
3. 配置界面：每个任务名称下，它出现过的每个列表一个复选框（勾选 = 该列表场景下放行并完成）。

## 方案

### 1. 新增选择表 `MiniGameTaskSelectMap`

新文件 [MiniGameTaskSelectMap.java](file:///d:/gitcode/Sesame-GR/app/src/main/java/io/github/lazyimmortal/sesame/util/idMap/MiniGameTaskSelectMap.java)，完全仿照现有 [MiniGameTaskListMap.java](file:///d:/gitcode/Sesame-GR/app/src/main/java/io/github/lazyimmortal/sesame/util/idMap/MiniGameTaskListMap.java) 的模式：

- `Map<String, List<String>>`：任务名 → 用户勾选的 listTitle 集合，`ConcurrentHashMap` + `synchronized` 落盘；
- 持久化文件 `MiniGameTaskSelect.json`（FileUtil 新增 `getMiniGameTaskSelectMapFile()`，仿 [FileUtil.java#L608-L614](file:///d:/gitcode/Sesame-GR/app/src/main/java/io/github/lazyimmortal/sesame/util/FileUtil.java#L608-L614)）；
- 对外 API：`containsScene(key, scene)`（执行门控用）、`toggle(key, scene, checked)`（UI 勾选写入选+落盘）、`clear()`、`load()/save()`、`ensureLoaded()`，均仿收集表实现。

### 2. 收集时默认勾选（维持现有自动行为）

在 [MessageUtil.java#L372](file:///d:/gitcode/Sesame-GR/app/src/main/java/io/github/lazyimmortal/sesame/util/MessageUtil.java#L372) 的 `MiniGameTaskListMap.add(taskTitle, listTitle)` 处，**仅当该 (task, list) 是首次收集时**同步 `MiniGameTaskSelectMap.toggle(taskTitle, listTitle, true)`。

实现细节：`MiniGameTaskListMap.add` 目前重复收集会直接 return，需在 MessageUtil 侧先 `containsScene` 判断、未收集过时再 add + 默认勾选。这样今天的「自动放行」行为无缝延续（= 不改变现有逻辑），用户可手动取消勾选。

### 3. 配置 UI：收集弹窗加复选框

改 [MiniGameTaskListModelField.java#L61-L114](file:///d:/gitcode/Sesame-GR/app/src/main/java/io/github/lazyimmortal/sesame/data/modelFieldExt/MiniGameTaskListModelField.java#L61-L114) 的 `showDialog`：

- 任务名称 TextView 保持不变；
- 下方原来的「场景：xxx，xxx」TextView 改为**每个场景一个 CheckBox**（横向 LinearLayout 包裹，文本直接显示 listTitle）；
- CheckBox 初始勾选状态 = `MiniGameTaskSelectMap.containsScene(task, scene)`；切换监听调 `MiniGameTaskSelectMap.toggle(task, scene, isChecked)` 即时落盘；
- 「清空」按钮追加 `MiniGameTaskSelectMap.clear() + save()`，两张表一起清；
- 不存配置、不注册新设置项，弹窗入口仍是「设置-基础-游戏任务收集列表」按钮。

### 4. 执行门控：10 处放行判据换读选择表

- `MiniGameTaskListMap.remove` 目前无人调用，不动。

## 验证

1. `gradlew assembleNormalRelease`（或现有 build 脚本）编译通过；注意项目 minSdk 21，不用 API24+ 方法；
2. 运行后让某个游戏任务触发 400000040 → 运行日志出现「收集游戏任务🎮」→ 打开 设置→基础→游戏任务收集列表，该任务名下场景复选框**默认勾选**；
3. 取消勾选后下一轮运行：该任务恢复黑名单跳过（日志不再出现「🕓已触发」）；重新勾选后下一轮恢复触发备用通道（日志出现「🕓已触发[任务名]…结果以任务列表为准」）；
4. 「清空」后两张表均空，弹窗显示空占位文案；
5. 重启进程后勾选状态从 `MiniGameTaskSelect.json` 正确恢复。
